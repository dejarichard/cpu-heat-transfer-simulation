Browser Hardware Sandbox Architecture

W3C Compute Pressure + Thermal Ohm's Law Solver

Why browsers cannot directly read motherboard thermistors: Modern web browsers enforce strict OS security sandboxing to prevent side-channel attacks (such as Spectre/Meltdown thermal timing leaks) and block direct ring-0 access to CPU Model-Specific Registers (MSRs) or SMBus sensor chips.

How THERMALFLUX bridges this gap:

  • W3C Compute Pressure API: Queries OS-level CPU telemetry states (nominal, fair, serious, critical) when supported by the browser.
  • Multi-Core Web Worker Stress Engine: Spawns real background threads executing floating-point & prime workloads while measuring main-thread event-loop jitter.
  • Coupled Cauer RC Thermal ODE Model: Solves transient heat conduction and convection ($dT/dt = (P_{\text{in}} - Q_{\text{out}})/C_{\text{th}}$) across Silicon Die, TIM, Copper IHS, and Heatsink nodes.
  • External Sensor Log Ingestion: Directly imports real hardware telemetry CSV/JSON logs exported from HWiNFO64 or CoreTemp.
